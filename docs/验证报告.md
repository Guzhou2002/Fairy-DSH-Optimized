# Fairy-DSH 实测验证报告

整理版 `v0.1.0` ｜ 验证日期 2026-09-12 ｜ 环境：本机 DSH `0.1.2-rc.1`、Node 24.20、pnpm 11.25

本报告记录整合包在本机的实测过程与结论，供安装前判断与升级后回归参考。
所有测试均在**隔离 DSH_HOME** 中进行，未接触生产 profile。

---

## 一、验证方法

1. 新建临时 `DSH_HOME`，profile 仅含官方 `@deepseek-ai/dsh-base` + `@deepseek-ai/dsh-web-app`，
   再用 `inject: [clientModules]` 插入 `dsh-fairy-visual`。
2. 通过 `dsh plugin --profile ... add link:` 链入插件包（触发真实加载路径）。
3. 写入 `settings.yaml` 打开开关（插件默认 `enabled: false`）。
4. `dsh --profile ... --no-open --port <空闲端口>` 启动实例。
5. 无头 Chrome 经 CDP 载入 UI，采集：
   - 宿主侧与客户端侧的 `DSH_FAIRY_LOG` 结构化日志
   - DOM 属性/节点统计、计算样式、元素几何
   - `Runtime.exceptionThrown` 与 console 输出
   - 页面截图（人工目视确认）
6. 结束后 `taskkill` 清理进程并删除临时目录。

复现命令：`.\verify-isolated.ps1`（`-Keep` 保留临时目录与截图）。

## 四、唯一降级项

```
[dsh-fairy-visual] degraded official capability [ENHANCEMENT]: balanceAction
 ([data-slot="sidebar.footer.action"] *[aria-label^="DeepSeek 余额"],
  [data-slot="sidebar.footer.action"] *[aria-label^="DeepSeek balance"])
```

**原因**：该隔离 profile 未安装 `dsh-balance-meter`，官方侧栏没有余额入口，
故 Fairy 找不到可挂载的锚点。**这是配置差异而非版本不兼容** ——
执行 `.\install.ps1 -Plugins visual,balance` 后该项即消失。

级别为 `ENHANCEMENT`，插件按设计降级而非报错。

## 五、未覆盖项

| 项 | 原因 |
| --- | --- |
| hero 文案投影（隐藏官方 headline、改写 textarea placeholder） | 需要打开工作区进入会话视图；无头环境下"选择工作区"会弹出系统目录选择框，故在交互边界止步 |
| composer 坞拖拽交互 | 同上，需要真实会话视图 |
| `fairy-voice` 实际出声 | 需要本机 GPT-SoVITS 于 `127.0.0.1:9880`，本机未部署 |
| `browser-dock` 截图 Dock | 需要 `@playwright/mcp`，且该插件不建议安装 |
| 长时间运行的资源占用 | 插件含 `document.body` 级 MutationObserver、rAF 动画与定时器，未做长时间压测 |

上述未覆盖项中，hero 投影与 composer 坞均采用「快照 → 改写 → 可还原」策略
（保存 `previousSeatStyle`、dispose 时还原 placeholder），风险有限。

## 六、兼容性根因

`@deepseek-ai/dsh-settings` 的导出在两个 rc 之间发生了变化：

| 版本 | 导出 |
| --- | --- |
| `0.1.1-rc.2`（插件 pin 的版本） | 含 `settingsNamespace`、`installSettingsSection` 等 |
| `0.1.2-rc.1`（本机宿主） | 仅 `SettingsConflictError`、`SettingsProvider`、`redactSecrets` |

插件依赖被精确 pin，pnpm 为其安装独立副本，因此导入成功；
`settingsNamespace()` 的实现只是「校验命名空间格式后原样返回字符串」，
与宿主 `SettingsProvider.register(ns, schema)` 的入参约定一致，故运行时无冲突。

**结论**：该 pin 是插件在当前 DSH 上可用的前提，不可提升或覆盖。
若未来官方恢复/变更该 API，需重新评估。

## 七、`fairy-voice` 专项（v0.1.1 追加）

隔离 profile（`-Plugins visual,voice`）实测：

| 检查项 | 结果 |
| --- | --- |
| 宿主 `apply` | ✅ success |
| 客户端 `apply` | ✅ success（visual / voice 各一条） |
| voice 样式表 `dsh-fairy-voice-controls-style` | ✅ 已注入 → 客户端插件确实加载 |
| `speechSynthesis` 可用性 | ✅ true |
| 中文嗓音 `getVoices()` | ⚠️ 无头 Chrome 返回 `[]`（真机 Chrome 才有微软中文语音，故音频输出无法在无头环境验证） |
| 朗读控件 `.dsh-fairy-voice-auto` | ➖ 计数 0 —— 该控件挂在 `conversation.input.left`，属**会话视图** slot；隔离实例停在"选择工作区"界面，未挂载 |

宿主侧另有一条**预期内的降级**警告：

```
module: "dsh-fairy-voice", operation: "reference.prompt.load", event: "failure",
context: { file: "fairy_ref.txt", fallback: true },
error: ENOENT … ~/.dsh/fairy-voice/runtime/reference/fairy_ref.txt
```

即缺少参考音频（作者私有音色素材，仓库不含），宿主优雅回退到内置提示词，不报错。

### 关键结论

1. **`fairy-voice` 没有任何语音输入能力**：全包检索 `getUserMedia` / `MediaRecorder` /
   `SpeechRecognition` / `whisper` / `STT` / `ASR` / 麦克风 均为零命中。
   `conversation.input.left` 这个名字容易被误读 —— 它挂在输入区左侧，但内容是
   「朗读 / 自动朗读 / 音量」，属于输出侧。
2. **输入区控制器有双重前置条件**：`conversation.input.left` 的组件在
   `document.documentElement` 没有 `data-dsh-fairy-visual` 属性时直接 `return null`
   （源码注释："In normal DSH mode this slot has no Voice surface or controller at all"）。
   因此它**必须**与 `fairy-visual` 且 HDD 模式开启搭配使用。
3. **宿主 `/prepare` 不依赖 9880**：它只做本地文本切句
   （`sentencePreparation.sentences(markdown)`），只有 `/tts` 才需要本机 GPT-SoVITS。
   这正是"切到浏览器引擎后整条链路可离线"的依据。
4. 上游把 `engine` 硬编码为 `'fairy'` 并注释说明是为了防止退化成系统嗓音；
   本包按使用者选择切到 `'system'`，属**有意偏离上游设计**，已在 README「本地改动」中标注。

## 八、回归建议

1. DSH 升级后先执行 `.\verify-isolated.ps1`，看是否仍为 `RESULT: PASS`。
2. 关注 `DSH_FAIRY_LOG` 中 `operation: "capability.missing"` 的条目数量变化 ——
   数量增加说明官方 DOM/ARIA 契约发生漂移，功能在静默减少。
3. 若出现 `exceptionThrown` 或 `apply` 不再 success，先 `.\uninstall.ps1` 回滚再排查。
