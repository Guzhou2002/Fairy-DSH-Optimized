## 3. 这一轮新学到的（重要，别再踩）

### 3.1 🔴 预设是「插件运行时」装的，不是 `install.cmd` 干的

以前以为"预设靠 `install.cmd` 复制"，**错了**（`install.cmd` 只是重复劳动）。真正的链路：

```
包内  PLUGIN_ROOT/.agent-presets/fairy        ← 源（跟包一起走）
家目录 ~/.dsh/.agent-presets/fairy            ← 目标（DSH 从这儿读预设）
面板开关  POST /fairy-persona/toggle  →  宿主 setPresetEnabled()  →  rm + cp（无条件整份覆盖）
```

**推论**：
- 用户「关掉再打开」那个开关 = 强制重灌 —— 这是**应急修法**，不用重装、不用重跑 `install.cmd`
- **但旧版（≤0.3.5）里没有别的刷新时机** —— 所以"更新了包却修不好"是必然的。v0.3.6 才补上启动同步

### 3.2 🔴 「发版 ≠ 修好」：凡是改**用户家目录里的东西**，先问"老用户怎么拿到新的？"

- 包更新了、家目录里那份还是旧的 → 老用户**一个字都没变**
- 以后改预设 / 配置模板 / 任何家目录产物，**必须同时想清楚刷新时机**，否则群里会收到"我装了新版还是坏的"
- 这条是本轮最贵的教训（差点让 v0.3.6 白做）

### 3.3 🟡 指纹别用 mtime，用内容哈希

tgz 每次解压出来的 mtime 都不一样 → 用 mtime 做指纹会退化成"每次启动都重灌"。
现在用 sha256（相对路径 + 文件内容）。

### 3.4 🟡 "只同步一次"必须先判断**目标是否存在**

否则用户关掉开关（= 删掉目标），重启后又被自动装回来 —— 开关等于失灵。
现在的规则：**目标不存在 → 什么都不做**。

### 3.5 🟢 验"启动时的行为"不必真启动 DSH

写个 `%TEMP%\fairy-*.mjs`：设好 `DSH_HOME` → `import` 包的 `lib/index.js` → 假 ctx `apply({ inject() {} })`，
三行就能跑通 `updated` / `unchanged` 两条路径，比反复重启便宜得多。
⚠️ 但它**替代不了** `verify-isolated.ps1` 的"真加载"和真机的"肉眼点一下"。

### 3.6 🟢 查「面板某个按钮绑了哪条路由」：两步就定位

① `grep` 面板源码 `lib\settings-merge.ps1` 里的 `fetch('/...')` → 拿到路由名
② `grep` 宿主 `lib\index.js` 里的 `webServer.register` → 拿到 handler → 再看 handler 调了谁

> 📌 **面板的所有逻辑都在 `lib\settings-merge.ps1` 里**（它是面板源码，不是生成物）；
> 生成物只有两个 `client.js`。
