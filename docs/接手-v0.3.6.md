## 3. 这一轮新学到的（重要，别再踩）

### 3.1 🔴 预设是「插件运行时」装的，不是 `install.cmd` 干的

以前以为"预设靠 `install.cmd` 复制"，**错了**（`install.cmd` 只是重复劳动）。真正的链路：

```
包内  PLUGIN_ROOT/.agent-presets/fairy        ← 源（跟包一起走）
家目录 ~/.dsh/.agent-presets/fairy            ← 目标（DSH 从这儿读预设）
面板开关  POST /fairy-persona/toggle  →  宿主 setPresetEnabled()  →  rm + cp（无条件整份覆盖）
```

**推论**：
- 用户「关掉再打开」那个开关 = 强制重灌 —— 这是**应急修法**，不用重装、不用重跑 `install.cmd`
- **但旧版（≤0.3.5）里没有别的刷新时机** —— 所以"更新了包却修不好"是必然的。v0.3.6 才补上启动同步

### 3.2 🔴 「发版 ≠ 修好」：凡是改**用户家目录里的东西**，先问"老用户怎么拿到新的？"

- 包更新了、家目录里那份还是旧的 → 老用户**一个字都没变**
- 以后改预设 / 配置模板 / 任何家目录产物，**必须同时想清楚刷新时机**，否则群里会收到"我装了新版还是坏的"
- 这条是本轮最贵的教训（差点让 v0.3.6 白做）

### 3.3 🟡 指纹别用 mtime，用内容哈希

tgz 每次解压出来的 mtime 都不一样 → 用 mtime 做指纹会退化成"每次启动都重灌"。
现在用 sha256（相对路径 + 文件内容）。

### 3.4 🟡 "只同步一次"必须先判断**目标是否存在**

否则用户关掉开关（= 删掉目标），重启后又被自动装回来 —— 开关等于失灵。
现在的规则：**目标不存在 → 什么都不做**。

### 3.5 🟢 验"启动时的行为"不必真启动 DSH

写个 `%TEMP%\fairy-*.mjs`：设好 `DSH_HOME` → `import` 包的 `lib/index.js` → 假 ctx `apply({ inject() {} })`，
三行就能跑通 `updated` / `unchanged` 两条路径，比反复重启便宜得多。
⚠️ 但它**替代不了** `verify-isolated.ps1` 的"真加载"和真机的"肉眼点一下"。

### 3.6 🟢 查「面板某个按钮绑了哪条路由」：两步就定位

① `grep` 面板源码 `lib\settings-merge.ps1` 里的 `fetch('/...')` → 拿到路由名
② `grep` 宿主 `lib\index.js` 里的 `webServer.register` → 拿到 handler → 再看 handler 调了谁

> 📌 **面板的所有逻辑都在 `lib\settings-merge.ps1` 里**（它是面板源码，不是生成物）；
> 生成物只有两个 `client.js`。

## 9. 🔴 v0.3.7：这一轮的后半段（我犯的错 + 兼容层）

> **v0.3.6 只修好了一半** —— 它**修好一台、弄坏了另一台**。这一节是那次的完整教训。

### 9.1 事实：`text:` / `prefix:` 是**跟着 DSH 版本走的**

| 机器 | `dsh-persona` 要的键 | 事实来源 |
| --- | --- | --- |
| 群友那台 | **`prefix:`** | 他的报错：`$.prefix missing required value (at prefix)` |
| 本机 | **`text:`** | 改完后本机报：`$.text missing required value (at text)` |

**两个都必填**，缺了就直接"预设挂载失败 → 会话创建被回滚"，
而客户端把失败吞成一条 `console.warn` —— 所以看起来**界面完全正常，只是点新建会话没反应**。

### 9.2 🔴 我犯的错：**拿单台机器的报错当成通用结论**

v0.3.6 只看到群友那台的报错（`prefix`），就断定"上游的 `text:` 是错的"，
把预设改成了 `prefix:` —— **发出去之后，本机立刻开不出会话了**。

**规矩（以后照做）**：
- 涉及**外部契约**（DSH 的 schema / DOM / 路由）的改动，**至少要两个来源**才能下结论；
  只有一个报错样本时，**先问"会不会是版本差异"**，并明确写出"这只在一台机器上验过"
- **改预设 / 改契约字段之后，必须真机点一下新建会话** —— 这是本轮唯一能定案的证据

### 9.3 ✅ 兼容层：同一段语料挂**两个键**

位置：`fairy-visual\dsh-fairy-visual\.agent-presets\fairy\agent.cordis.yml` 的 `persona` 行。

```yaml
- id: persona
  name: '@deepseek-ai/dsh-persona'
  config:
    # [compat 0.3.7] 旧版 DSH 的 persona 只认 text:，新版只认 prefix:
    #               两边都会忽略自己不认识的键 —— 所以两个都写，谁认识谁拿
    text: |-            # ← 老版 DSH 用这个
      （人设语料 35 行，原样）
    prefix: |-          # ← 新版 DSH 用这个（同一段语料，逐字相同）
      （同上）
```

**为什么成立**：两台的报错都**只抱怨"少了我认识的那个键"**，
**从没抱怨过"多了个我不认识的键"** → schema **忽略陌生键**。
→ 判据一句话：**要证明"多写一个键安全"，就看报错里有没有"unrecognized key"**。

**为什么不用"按版本生成不同的键"**：插件拿不到宿主 persona 的 schema，判版本又脆。
双键**不依赖版本号** —— 以后 DSH 再改键名，只要还是这两个之一就都活着。

### 9.4 🟡 改这种文件的**正确姿势**（我这次中途插错过一行）

- **不要在"原键行"上做插入** —— 我第一次把 `text:` 插在了 `prefix:` **前面却没删原行**，
  结果 `config:` 下出现了 `prefix: |- / 注释 / text: |- / … / prefix: |-`，YAML 直接坏掉。
  正确做法：**替换**那一行，或**先删后插**，并在写盘前断言
  「`text:` 恰好 1 个、`prefix:` 恰好 1 个」
- **写盘前断言、断言失败就 `throw`** —— 这次救了我：报错发生在写盘之前，文件一个字没动
- 改完**必须机器校验两段语料逐字相同**：`-ceq` 比较两个 block（别用肉眼看）
- 复检要靠 **`git diff --stat`**：应该是 **`37 insertions(+), 0 deletions(-)`**
  —— **有 deletion 就说明语料被动过**（红线）

### 9.5 🟢 家目录的预设可以**不重启**就改好

直接 `Copy-Item` 覆盖 `~/.dsh/.agent-presets/fairy/agent.cordis.yml`，
再 **Ctrl+F5 + 点新建会话**即可验证 —— **会话创建时才读预设，不是启动时缓存**。
（真正要重启的只有"仓库里的插件代码"`lib/*.js`）

> 顺带：仓库是 `link:` 装的话，家目录那份和包内那份**是两份**，改完仓库要记得同步过去。
