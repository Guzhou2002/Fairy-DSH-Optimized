## 4. 我做的修改

### 4.1 分发与安装（本分支核心价值）

- `install.ps1` + `install.cmd`：数字键菜单选插件（1 视觉 / 2 +语音 / 3 +余额 / 4 全部 5 个 / 5 自定义），7 步流程含依赖检查、设置栏合并、人设预设安装、配置备份、`dsh plugin add` 注册、遗留块清理、profile 校验
- `uninstall.ps1` + `uninstall.cmd`：5 步，只移除实际存在的依赖
- `verify-isolated.ps1` + `verify.cmd`：临时 `DSH_HOME` 起隔离实例 + 无头浏览器探针，**不碰使用者现有 profile**
- `build-release.ps1`：产出两个 zip（一键安装版 / 一键部署版-含依赖）+ `.sha256`，默认输出到包内 `release\`
- `安装说明.txt`：傻瓜版图文步骤（含第八步人设、第九步朗读自检 9.1–9.4）

### 4.2 部署机制（0.2.1 起）

每个插件包的 `package.json` 声明 `dsh.bundle.patch` + 自带 `cordis.patch.yml`，于是 `dsh plugin add` **一条命令**即可完成依赖链接 + `dsh.profile.bundles` 注册。

### 4.3 可独立分发（0.2.0–0.2.1）

- `dsh-fairy-contracts` 依赖**内联**进各包 `vendor/`（源码级复制），依赖里移除
- 依赖布局改 **hoisted 扁平**（各包 `pnpm-workspace.yaml: nodeLinker: hoisted`），`node_modules` 内**零符号链接**，解压即用

### 4.4 设置栏合并

`lib/settings-merge.ps1` 从 `upstream-originals\` 的原件**生成**两个客户端的合并包：

- `fairy-visual\…\lib\client.js` ← 注入 `FairyNotice`（顶部声明行）+ `FairyVoicePanel`（自检面板 / 配置 / 人设开关），标签统一为 **Fairy**

## 9. 注意事项（踩过的坑，别重踩）

1. **`.ps1` 必须 UTF-8 带 BOM**：编辑工具常把 BOM 弄丢 → PowerShell 5.1 按 GBK 读 → 满屏假语法错。改完必须补 BOM + `Parser::ParseFile` 校验
2. **PowerShell 两个坑**：`\"` 不是转义（反斜杠是原样，会截断字符串）；`$url?name=` 里的 `?` 会被当成变量名的一部分，要写 `${url}?name=`
3. **绝不要在这个目录跑 `git clean -fd`**：`node_modules` 与 `release/` 都在忽略列表里，跑一下插件当场加载不了
4. **`lib\client.js` 是生成物**：合并上游时**不要直接接受上游对它的改动**，要先把新版存进 `upstream-originals\` 再重新生成（见 `docs\仓库与上游.md` §4.2）
5. **人设预设已搬进插件包**：上游更新语料时 git 会报 `deleted by us`，要手动同步进 `fairy-visual\dsh-fairy-visual\.agent-presets\fairy\`；且 `agent.cordis.yml` 里那两条私有 runtime 引用要**保持移除**
6. **GitHub Release 附件名不能含中文**（会被清洗成 `-.zip`）；正文要写中英对照表
7. **live profile 用 `link:` 指向本目录**：任何改写文件的 git 操作（checkout / merge / reset --hard）会**立刻影响正在运行的 DSH**；规矩是"先提交再切分支/合并"
8. **本机网络**：GitHub 大文件下载会卡（`git clone`、Release 附件下载），但 API 与 `ls-remote` 正常 —— 别用"下载回来验证"当默认手段
9. **别把正在跑的 DSH 当残留进程杀掉**：GUI 监听 `127.0.0.1:3080`（曾差点误杀，清理前先按端口/命令行确认归属）
10. **对外口径**：本项目是**非官方**整理分支，README / 安装说明 / Release 正文都已写明"问题请反馈到本仓库或群，不要打扰上游作者"
11. **改完文档要重打包**：`安装说明.txt` 在 zip 里，改它就等于改包 → SHA 会变 → Release 附件与正文 SHA 必须同步更新，tag 也要对齐
12. **git 的代理要单独配**：本机梯子**只给浏览器指路**，git 默认裸连，会报 `Failed to connect to github.com:443 after 21xxx ms`（有时还报 `schannel: SEC_E_NO_CREDENTIALS`）。
    **排障三步**：① 看系统代理 `HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的 `ProxyServer`；② 看那个端口在不在监听；③ 看 `git config --get-regexp proxy` 是不是空的（空的 = 就是它）。
    **修复**：`git config --global http.https://github.com.proxy http://127.0.0.1:7897`（**换梯子端口后要同步改**）。
    **撤销**：`git config --global --unset http.https://github.com.proxy`。
    > ⚠️ 原先"本机网络 GitHub 大文件下载会卡"的结论是**误诊** —— 真正原因是 git 没走代理。配好后 `ls-remote`/`push` 都正常。
13. **`upstream-pull-request\` 是 git worktree，不是普通文件夹**：它和主仓库**共享 `.git`**。
    ① 它已被写进 `.git/info/exclude`（**本地忽略，不动 `.gitignore`**）；
    ② **绝不要在主仓库跑 `git add -A`**，否则可能把整份上游代码提交进 main；
    ③ 要删它用 `git worktree remove upstream-pull-request`，**别直接删文件夹**（会留下脏元数据）；
    ④ `git worktree list` 可以看到两个工作区。
14. **🔴 `install.cmd` 必须是 GBK 编码 + `chcp 936`，绝不能存成 UTF-8**（排查了一整轮的血泪教训）：
    UTF-8 的中文在 **936 代码页**的系统上会让 `cmd.exe` 认错行尾换行符，
    于是 `rem` 注释行被**从中间切开当成命令执行**，满屏
    `'xx' is not recognized as an internal or external command`，安装必然失败。
    - **症状**：双击后开头一堆乱码报错，但标题和部分 `echo` 行又显示正常，很有迷惑性
    - **为什么在开发机复现不出来**：本机 ANSI 代码页是 **65001**（Win11 开了全局 UTF-8），恰好躲过这个 bug
    - **判别方法**：`chcp` 显示 **936 = 会中招**，显示 65001 = 不会
    - **改完必须**：GBK 严格编码写回 + 全 CRLF + 无 BOM + `chcp 936`；
      且不能出现 GBK 存不下的字符（emoji 等，原 `✅` 已因此删掉）
    - **验证方法**：本地空跑（把 `call dsh plugin` 块和 `robocopy` 行换成 `echo`）应 **0 条解析错误**；
      但**本机验证不算数**，最终必须在真机（936）跑一遍
    - 原理参考：http://www.bathome.net/forum.php?mod=viewthread&tid=68945
