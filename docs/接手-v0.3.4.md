## 3. 这一轮新学到的（重要，别再踩）

### 3.1 🔴 `node --check` 抓不到「调用了一个没导入的符号」

这是 v0.3.2 翻车的根因：语法完全正确，**只有真启动才炸**（`ReferenceError`）。

**衍生铁律**：
- 任何改了 `lib/*.js` 的版本，**推之前必须真启动一次**（隔离验证也算）
- **包发出去前必须解包验符号**：
  ```powershell
  tar -xzf .\release\dsh-fairy-voice.tgz -O package/lib/index.js | Select-String 'ensureFairyDirectories'
  ```
- 已写进 `docs\交接摘要.md` §8 的「发版铁律」

### 3.2 设置面板的源码在 `lib\settings-merge.ps1`，不在上游原件里

| 容易以为 | 实际 |
| --- | --- |
| 面板在 `fairy-voice` 的 client.js | ❌ 面板注入到 **`fairy-visual\dsh-fairy-visual\lib\client.js`** |
| 改上游原件才对 | ❌ 面板源码就在 **`lib\settings-merge.ps1`** 里 → 改它、再重跑 `Set-SettingsMerge` |

### 3.3 装了新程序，**已在运行的进程看不到**

`gh` 装好后当前进程仍报 `not recognized` —— PATH 是进程启动时的快照。
**解法**：用全路径调用，或重启那个进程。

### 3.4 MOSS 合成有随机性 —— **"听一次就下结论"不可靠**

实测：同一文本、同一份参考音频，两次生成**时长差 10\~17%**（语速/停顿全然不同）、peak 差 2.5 dB。
→ 之前那次「把 `PLAYBACK_GROUP_SIZE` 从 4 改成 2、听完说'很孬'」的判断，很可能是抽到了噪声。

### 3.5 音色几乎 1:1 继承自参考音频

| 参考音频自身 hfRatio | 合成产物 hfRatio |
| --- | --- |
| 0.0988（干净） | 0.117 |
| 0.1763 | 0.198 |
| 0.2417（很毛） | 0.245 |

→ **参考干净，念出来就干净**。
而且那些"毛"**不在 14 kHz 以上**（实测 14 kHz 低通几乎没削掉任何东西）—— 它落在人声/齿音频段，
**滤不掉，只能换素材**。所以别用「降噪」「人声增强」处理过的音频，处理痕迹会被一起学过去。

### 3.6 工具层面的坑

- **`pwsh` 读 UTF-8 中文文件命令行显示乱码**：文件本身没坏，别被误导
- **提取 Markdown 里的特殊标记**：用**码点定位**（`[char]0x25BC`）比正则可靠
- **`Select-String` 查生成物**：先确认面板注入在哪个包，别白查一轮
- **同文件的多次 `edit` 要分轮做**：并行发可能互相覆盖

## 4. 常用命令

```powershell

# 改了 lib\settings-merge.ps1 之后必做（会重新生成 visual 的 client.js）

$t=[IO.File]::ReadAllText((Resolve-Path $p))
[IO.File]::WriteAllText((Resolve-Path $p),$t,(New-Object Text.UTF8Encoding($true)))   # edit 工具会丢 BOM
```
