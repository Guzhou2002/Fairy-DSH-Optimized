# 安装机制实测：`dsh plugin add` 到底做了什么

> 验证日期：**2026-09-13** ｜ 环境：DSH `0.1.2-rc.1`、Node 24.20、pnpm 11.25、Windows
> 全部实测在**临时 `DSH_HOME`** 中进行，**未接触** `~/.dsh/profiles/web`（每次测试后已核对 profile 时间戳未变）。
>
> **一句话结论**：`dsh plugin add` 官方命令**一步到位**（下载 + 装依赖 + 注册 bundle），
> **`install.ps1` / `uninstall.ps1` 可以废掉**，包体积能从 1.8MB 降到 ~374KB。

---

## 1. `dsh plugin` 的真身是 pnpm

```console
$ dsh plugin --profile web --help
Version 11.25.0
Usage: pnpm [command] [flags]
```

**`dsh plugin --profile <名> <命令>` = 在 `~/.dsh/profiles/<名>` 目录里执行 `pnpm <命令>`。**
`-C, --dir <dir>` 默认值就是那个 profile 目录。

所以 pnpm 支持的形态它全支持：

```
pnpm add <name>              ← npm 包名
pnpm add link:<dir>          ← 目录符号链接
pnpm add file:<dir>          ← 目录复制
pnpm add <tarball file>      ← 本地 .tgz
pnpm add <tarball url>       ← 远程 .tgz（未实测，机制同 file:）
pnpm add <git host>:<user>/<repo>
```

---

## 2. 三种形态对比（实测）

| 形态 | 是否装依赖 | 实测证据 |
| --- | --- | --- |
| **`link:<目录>`** | ❌ **不装** | `Done in 520ms`，零下载；`node_modules` 里只有一个 **Junction**，没有 `@deepseek-ai`；目标包自己也没生成 `node_modules` |
| **`file:<目录>`** | ✅ 装 | `Packages: +9`（`@deepseek-ai+dsh-settings` / `+schemastery` / `+cordis` / `+cosmokit` / `+dsh-brand` / `+dsh-invariants` / `@standard-schema+spec`） |
| **`<xxx.tgz>`** | ✅ 装 | `Packages: +9`，且 **bundle 自动注册成功** |

> ⚠️ **这条解释了过去的一个误解**：`install.ps1` 里预装 `node_modules` 之所以必要，
> **不是因为"pnpm add 不装依赖"，而是因为你用的是 `link:` 形态。**

---

## 3. 关键发现：`link:../../fairy-contracts` 相对**安装者的工程目录**解析

实测时 pnpm 给出的警告（`file:` 与 `tgz` 两次测试都出现）：

```
[WARN] Installing a dependency from a non-existent directory:
       C:\Users\1\AppData\Local\Temp\fairy-tgztest-20260913-135242\home\fairy-contracts
```

**注意这个路径**：`...\home\` 正是那次测试的 **`DSH_HOME` 根目录**，不是包自己的目录。

**结论**：上游写的 `"dsh-fairy-contracts": "link:../../fairy-contracts"` 在**任何**非 monorepo 环境下
都不可能解析成功。**这就是它必须被删掉（改 vendor 内联）的根本原因。**

---

## 4. 全链路验证：tgz + 已完成 vendor 化的包

实验体：本仓库的 `fairy-visual/dsh-fairy-visual`（已 vendor 内联、已删 `dsh-fairy-contracts` 依赖），
用 `robocopy /XD node_modules` 排除依赖后 `pnpm pack`。

| 检验项 | 结果 |
| --- | --- |
| tgz 大小 | **382,868 字节（374KB）** —— 现有 zip 是 1.8MB，**小约 5 倍** |
| tgz 内含 `cordis.patch.yml` | ✅ |
| tgz 内含 `vendor/` | ✅ `client-dom.cjs` / `diagnostics.js` / `fairy-contracts.js` |
| **tgz 内含人设预设** | ✅ `package/.agent-presets/fairy/**` 全部在内 |
| `dsh plugin add <tgz>` | ✅ **exit 0，1.1 秒** |
| 依赖自动安装 | ✅ `Packages: +9` |
| **bundle 自动注册** | ✅ `"dsh-fairy-visual"` 自动进了 `dsh.profile.bundles` |
| 依赖解析警告 | ✅ **零警告**（因为已 vendor 化） |

### 一条命令装多个 —— 可行

```
dsh plugin --profile <名> add <tgz1> <tgz2>
→ Packages: +10
→ bundles 自动变成：
   ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app",
    "dsh-balance-meter", "dsh-fairy-visual"]        ← 两个都自己加上了
```

**所以 5 个插件可以一条命令装完。**

### 注册机制比想象的更简单

profile 里**不会**生成 `cordis.patch.yml`（`verify-isolated.ps1` 早期是手写这个文件的）。
DSH 读包里的 `dsh.bundle.patch` → 解析它指向的 `cordis.patch.yml` → **直接把 `name` 追加进 `dsh.profile.bundles` 数组**。

## 6. 遗留问题

| # | 问题 | 说明 / 可能解法 |
| --- | --- | --- |
| **1** | **人设预设不会自动安装** | tgz 里带着 `.agent-presets/fairy/`，但 DSH 只把**插件**装进 profile，**不会**复制预设到 `$DSH_HOME\.agent-presets\`。需保留一个极简复制脚本，或写成 1 条命令 |
| **2** | **本地 tgz 路径会被写进 profile** | profile 里存的是 `file:C:/.../xxx.tgz`。群友删掉 tgz 后，pnpm 再跑可能找不到 → 建议用 **远程 URL** 或 **npm 包**，路径才稳定 |
| **3** | `file:` 是**复制**安装，不是链接 | 更新插件要重新 `add`；本地开发仍建议用 `link:`（现有 live profile 就是 `link:`） |
| **4** | 远程 tarball URL 形态**未实测** | 机制同 `file:`（都是"非 link"），但没直接验过。要定案可以补测一次 |

## 7. 复现命令

```powershell
# A. 封装一个 tgz（排除 node_modules）
$stage = "$env:TEMP\pack-test"; New-Item -ItemType Directory -Force -Path $stage | Out-Null
robocopy 'C:\Users\1\.dsh\plugins\Fairy-DSH\fairy-visual\dsh-fairy-visual' $stage /E /XD node_modules /NFL /NDL /NJH /NJS /NP | Out-Null
Push-Location $stage; pnpm pack; Pop-Location

# B. 在隔离环境里装（不碰 live profile）
$iso = "$env:TEMP\iso-home"
$pd  = "$iso\profiles\t1"; New-Item -ItemType Directory -Force -Path $pd | Out-Null
'{ "name": "t1", "private": true, "dependencies": {},
   "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base","@deepseek-ai/dsh-web-app"] } } }' | Set-Content "$pd\package.json" -Encoding ascii
'[]' | Set-Content "$pd\cordis.yml" -Encoding ascii
$env:DSH_HOME = $iso
dsh plugin --profile t1 add "$stage\dsh-fairy-visual-0.1.0.tgz"

# C. 看结果
Get-Content "$pd\package.json" -Raw     # 应看到 bundles 自动多了一行
```

> 参考实现：`verify-isolated.ps1` 第 139–212 行（建临时 `DSH_HOME` + profile 的完整写法）。
